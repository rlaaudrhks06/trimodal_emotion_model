# A100 서버에서 회수한 것 — 무엇을, 왜, 어디에

학교 A100(`rookie-s11`)을 반납하기 전에 서버에만 있던 자산을 로컬로 옮겼다.
**서버가 사라지면 이 문서가 "그 데이터가 어디서 왔는지"를 아는 유일한 기록이 된다.**

회수일 2026-08-14. 서버 원본 경로는 전부
`/data/aihub_download/trimodal_emotion_model/` 아래였다.

## 원칙 — 원본만 받고 파생물은 버렸다

서버에 있던 132GB 중 **34GB만 가져왔다.** 기준은 하나였다:
**다시 만들 수 있으면 안 받는다.**

| 안 받은 것 | 크기 | 다시 만드는 법 |
|---|---:|---|
| `data/feature_cache/` | 84GB | `processed_full`에서 재생성된다. prosody 추출(`librosa.pyin`)이 느려 몇 시간 걸리지만 값은 동일하다 |
| v1~v9·v12a 체크포인트 | ~15GB | 재학습이 필요하지만, 분석은 예측 CSV로 대체된다(아래) |

버린 84GB가 아까워 보이지만, 저 캐시는 **얼굴 프레임을 uint8로 저장한 사본**일 뿐이다(8.19절).
원본이 있으면 값이 같은 것을 다시 만들 수 있고, 원본이 없으면 캐시가 있어도 재학습 레시피를
바꿀 수 없다.

## 받은 것

### 1. `data/processed_full/` — 27GB · **이게 본체다**

전신 bbox를 얼굴 크롭으로 고치고(8.8절) 재구축한 데이터셋이다.

```
audio/   80,122개 wav      10.9GB
faces/   80,122개 디렉터리  17GB   (프레임 2,165,735장, 전부 112×112)
```

이걸 잃으면 AI Hub 원본 15개 zip(약 120GB)을 다시 받아 얼굴 재검출 파이프라인을
처음부터 다시 돌려야 한다. 그 과정에서 겪은 것이 "백본을 세 번 갈아치웠는데 사실
얼굴을 준 적이 없었다"는 8.8절의 사고였다.

### 2. `data/manifests_si/` — 15MB · 화자 누수를 정리한 분할

```
train 56,694 / val 11,443 / test 11,464 = 79,601 발화
화자   200명 /    40명 /    40명,  중복 0명 (union-find, seed 2026)
```

8.14절에서 `person_id`가 클립 내 일련번호가 아니라 전역 화자 번호임을 발견한 뒤
다시 나눈 것이다. **v10 이후 모든 수치가 이 분할 위에서 나왔다.**

`split_manifest.py + seed`로 재현 가능하다고 적어뒀지만, 그건 `all.csv`가 있을 때
얘기다. 그래서 `data/manifests_full/all.csv`(79,601행)도 함께 받았다.

> 매니페스트는 **원본 8클래스(경멸 포함)** 상태다. 그대로 세면 최다 클래스가 23.56%인데,
> 경멸→혐오 병합 후 27.00%가 되어 문서의 기준선과 맞는다. 병합은 학습 코드가 로드
> 시점에 하므로 **매니페스트를 손대면 안 된다.**

### 3. `data/prosody_stats_*.json` — 3KB · 없으면 조용히 틀린다

| 파일 | 쓰는 config |
|---|---|
| `prosody_stats_train_si.json` | **v10~v12 (v11 포함)** — 지우면 안 된다 |
| `prosody_stats_train.json` | v3~v9 |

학습이 운율을 정규화했으면 추론도 같은 통계를 써야 한다. 없는 채로 돌리면 f0(수백 단위)와
jitter(0.01 단위)의 스케일이 학습 때와 달라지는데 **에러 없이 그럴듯한 답이 나온다.**
`robot/brain/engine.py`가 이걸 `SystemExit`으로 막는 이유다.

### 4. `checkpoints/` — 3.7GB

| 파일 | 파라미터 | 용도 |
|---|---:|---|
| `v11_best.pt` | 437,923,519 | **채택 모델.** 데모·젯슨 배포 |
| `v12b_best.pt` | 438,126,292 | val↑/test↓ 사례. 보험 |
| `v10_best.pt` | 122,087,231 | wav2vec2 도입 전 기준선 |

`best_model.pt`(120,263,372 / 8클래스 / mel frontend)는 삭제했다 — v1~v4 시절 것이라
경멸 병합·얼굴 크롭 수정·화자 재분할이 전부 반영되기 전 모델이다.

### 5. `models/wav2vec2-large-xlsr-53` — 1.2GB

v11이 실제로 쓴 백본. 맥 데모는 HF 허브 id로 대체해 돌지만, **젯슨 오프라인 배포**에는
로컬 사본이 필요하다.

### 6. `results/predictions/` — 11MB · **이번 회수에서 가장 값어치 있었던 것**

8.29.5절 규칙 3번이 이렇게 적혀 있었다.

> 평가 시 per-sample 예측을 저장한다 — 짝지어 검정과 사후 분석에 필요하다.
> **지금 v11↔v12b를 McNemar로 검정하지 못하는 이유가 이것이다**

서버 반납 전에 v9·v10·v12a·v12b를 다시 평가해 예측을 저장했다. 재평가 결과는 8일 전
json과 정확도·F1·혼동행렬이 전부 같았고 `evaluated_at`만 달랐다.

덕분에 그동안 못 하던 검정을 했다(8.31절):

```
v11 vs v12b   불일치쌍 1,943   z=2.52  p=0.012   유의
v10 vs v12a   불일치쌍 1,880   z=0.51  p=0.61    구분 안 됨
```

v12a의 test 정확도(43.95%)도 이때 처음 쟀다 — 그전엔 val(45.35%)만 있었다.

**이 CSV들이 있으면 원본 데이터가 사라져도 클래스별·화자별·길이별·짝지어 검정이
전부 가능하다.** 11MB로 84GB의 분석 능력을 산 셈이다.

| `v11_test.npz` | 융합 직전 모달리티별 표현 `z_v`/`z_a`/`z_t`/`h` (11,464 × 512) |

경고·중단 사유·lr 스케줄 이력은 여기에만 있다.

## 검증 — 서버를 지워도 되는지 어떻게 확인했나

옮겼다는 사실만으로는 안전하다고 말할 수 없어서, 다섯 가지를 확인했다.

| 항목 | 결과 |
|---|---|
| 파일 개수 | 오디오 80,122 · 얼굴 80,122 · 프레임 2,165,735 — 서버와 동일 |
| **총 바이트** | **23,956,252,602 — 서버와 완전 일치** |
| 매니페스트 참조 | 79,601개가 가리키는 wav·얼굴 경로 **누락 0** |
| 얼굴 규격 | 무작위 200개 표본 전부 112×112, 빈 디렉터리 0 |
| **실제 추론** | `ManifestEmotionDataset` → `CollateFn` → v11로 5건 추론, **저장된 예측과 5/5 일치** |

마지막 항목이 핵심이다. 개수와 용량이 맞아도 **A100에서 낸 예측을 맥에서 재현하지
못하면** 데이터·체크포인트·코드 중 어딘가가 어긋난 것이다. 5/5 일치는 셋이 완전히
정합함을 뜻한다.

> 처음엔 파일이 1개 많고 용량이 320MB 적게 나왔다. 원인은 macOS가 만든 `.DS_Store`
> 2개와, ext4가 디렉터리 엔트리에 쓰는 공간이었다(8만 개 디렉터리). 파일 내용은
> 1바이트도 다르지 않았다.

## 전송이 느렸던 이유와 해결

처음엔 rsync로 받았는데 얼굴 구간에서 기어갔다(약 97 디렉터리/분). 원인은
**얼굴 프레임이 216만 개의 작은 파일**이라는 것이었다 — rsync는 파일마다 프로토콜
왕복을 한다.

tar 스트리밍 4개를 병렬로 돌리고, 압축을 끄고(JPG·WAV는 이미 압축돼 있다),
AES 가속되는 cipher를 쓰자 **4,568 디렉터리/분**으로 올랐다. 약 47배다.

```bash
# 서버에서 목록을 4등분한 뒤
ssh a100 "cd $R && tar cf - -C faces -T /tmp/faces_part_$i" | tar xf - -C faces/
```

같은 상황(작은 파일 수백만 개)을 또 만나면 이 방법을 먼저 쓴다.

`data/processed_full/`과 `data/manifests_*/`는 AI Hub 파생물이므로
**공개 저장소·공유 링크에 올리면 안 된다.** `.gitignore`가 이미 제외하고 있다.

`results/predictions/`는 utt_id·정답·예측·확률만 담고 원문 텍스트가 없어 git에 올렸다.
