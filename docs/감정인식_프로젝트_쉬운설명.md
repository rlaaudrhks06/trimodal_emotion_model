# 반려 로봇 감정인식 모델 — 누구나 이해하는 프로젝트 설명서

이 문서는 전문 용어를 최대한 풀어서, 컴퓨터공학을 몰라도 "지금 뭘 만들고 있고, 어떤 기술을 어떤 수치로 적용했는지"를 정확히 이해할 수 있도록 쓴 안내서다. 코드에 실제로 적힌 숫자 하나하나를 빠짐없이 담되, 그 숫자가 "무엇을 뜻하는지·왜 그 값을 골랐는지"를 함께 풀어썼다. 이 문서 하나만 봐도 "이 프로젝트에 어떤 기술이 쓰였고, 각 설정값이 뭔지" 대부분의 질문에 답할 수 있는 걸 목표로 한다.

---

## 1. 무엇을 만들고 있는가

반려 로봇이 사람과 상호작용할 때, 카메라와 마이크만으로 **"이 사람이 지금 어떤 감정인지"**를 스스로 판단하게 만드는 것이 목표다.

사람은 감정을 읽을 때 한 가지 신호만 보지 않는다. 말의 내용, 말투(목소리 톤), 표정 세 가지를 동시에 참고한다. 그래서 이 모델도 세 가지 정보를 동시에 본다 — 이걸 **"트리모달(3개 형태)"** 이라고 부른다.

- **음성**: 목소리의 높낮이·떨림 등 "어떻게 말했는가"
- **텍스트**: 음성을 글자로 옮긴 것(STT) — "무엇을 말했는가"
- **영상**: 얼굴 표정 — "어떤 표정을 지었는가"

이 세 가지를 종합해서, **분노 / 혐오 / 공포 / 행복 / 슬픔 / 놀람 / 중립** 7개 감정 중 하나를 최종 답으로 내놓는다.

---

## 2. 모델은 어떻게 판단하는가 (비유로 설명)

이 모델은 "음성 전문가", "텍스트 전문가", "얼굴 전문가" 세 명이 각자 분석한 뒤, **서로의 의견을 참고해가며(교차 확인)** 최종 결론을 내는 구조다. 이 "서로 참고하는" 계산 방식을 기술적으로는 **크로스 어텐션(cross-attention)** 이라고 부른다.

세 전문가 중 두 명(텍스트, 얼굴)은 **이미 다른 곳에서 미리 훈련받고 온 전문가**를 데려다 쓴다(사전학습 모델). 음성 전문가만 예외로, 우리가 가진 데이터로 처음부터 직접 훈련시키고 있다 — 그래서 세 전문가 중 실력이 가장 약하다.

모델을 "학습시킨다"는 건, 정답이 달린 연습문제(발화)를 계속 풀리고, 틀릴 때마다 판단 기준(가중치)을 아주 조금씩 고쳐나가는 과정이다. 이때 연습문제(학습용)와 실력 테스트용 시험지(검증·평가용)를 반드시 분리해서, 학습 중엔 시험지 정답을 절대 보여주지 않는다.

---

## 3. 왜 어려운 문제인가

1. **감정은 원래 애매하다.** 실제 대화 속 감정은 경계가 흐릿해서 사람끼리도 의견이 갈린다.
2. **감정별로 데이터 양이 다르다.** 화남·혐오는 사례가 많은데 공포는 상대적으로 적다.
3. **비슷한 연구들의 결과도 냉정하게 보면 그리 높지 않다.** 비슷한 한국어 감정 데이터셋(KEMDy19)도 훨씬 유리한 평가 조건에서 정확도 66~69% 수준이다.

---

## 4. 모델 구조 — 정확한 수치 전부

### 4.1 전체 골격에서 공통으로 쓰는 값

| 설정 | 값 | 무슨 뜻인가 |
|---|---|---|
| `d_model` | **256** | 음성·텍스트·영상 세 정보를 전부 이 크기(256개 숫자로 된 벡터)로 통일해서 서로 비교·결합한다. 마치 서로 다른 나라 화폐를 전부 달러로 환산해서 비교하는 것과 비슷하다. |
| `n_heads` | **8** | 크로스 어텐션(서로 참고하는 계산)을 할 때, 한 번에 1가지 관점이 아니라 8가지 서로 다른 관점으로 동시에 비교한다("이 부분은 억양 관점에서 보고, 저 부분은 단어 의미 관점에서 본다"는 식으로 8명이 동시에 각자 관점으로 검토). |
| `ffn_dim` | **1024** | 각 어텐션 계산 뒤에 정보를 한 번 더 가공하는 내부 신경망의 크기. |
| `backbone_layers` | **2** | 음성·영상 전용 처리기(TemporalConvFrontend, 4.3·4.4절)가 내부적으로 몇 겹 쌓여 있는지. |
| `num_classes` | **7** | 최종적으로 구분하는 감정 개수(분노·혐오·공포·행복·슬픔·놀람·중립). |
| `prosody_dim` | **10** | 운율(말투) 정보를 10개 숫자로 요약해서 쓴다(피치 평균, 떨림 정도 등). |

> 계산해보면: `d_model`(256) ÷ `n_heads`(8) = **32**. 즉 8명의 "관점 담당자" 각자가 32개 숫자짜리 조각을 담당해서 256차원 벡터를 나눠 본다(트랜스포머 계열 모델의 표준적인 멀티헤드 어텐션 구조).

### 4.2 텍스트 처리 (BERT)

| 설정 | 값 | 무슨 뜻인가 |
|---|---|---|
| 사전학습 모델 | **`klue/bert-base`** | 이미 방대한 한국어 텍스트로 훈련된 언어모델(파라미터 약 1.1억 개). 문장을 넣으면 단어마다 768개 숫자로 된 의미 벡터가 나온다. |
| `text_freeze_layers` | **8** (v6·v8) 또는 **12** (v7) | BERT는 총 12개 층으로 구성돼 있다. 이 값은 "아래에서부터 몇 개 층을 고정(재훈련 금지)할지"다. 8이면 하위 8개 층은 그대로 두고 상위 4개 층만 우리 데이터로 살짝 더 훈련시킨다. 12면 전부 고정 — 사전학습된 지식을 아예 건드리지 않는다. |
| `text_dropout` | **0.2** | BERT 내부의 두 드롭아웃 값(`hidden_dropout_prob`, `attention_probs_dropout_prob`)에 동시에 적용. 원래 BERT 기본값(0.1)보다 높여서 더 세게 규제한다. ("드롭아웃"이 뭔지는 5.5절에서 한 번에 설명) |
| 입력 최대 길이 | **64 토큰** | 문장이 이보다 길면 잘라낸다. |
| 벡터 변환 | 768 → **256**차원 | BERT가 뱉는 768차원 벡터를 `d_model`(256)에 맞춰 압축하는 작은 선형 변환(nn.Linear) 하나를 거친다. |

### 4.3 음성 처리

이 부분만 사전학습 모델 없이 처음부터 훈련된다.

| 설정 | 값 | 무슨 뜻인가 |
|---|---|---|
| `sample_rate` | **16,000Hz** | 오디오를 1초에 16,000번 측정한 디지털 신호로 다룬다(표준적인 음성 처리 해상도). |
| `n_mels` | **80** | 소리를 "멜 스펙트로그램"이라는, 사람 귀가 느끼는 방식에 가깝게 주파수를 80개 구간으로 나눈 그림 형태로 변환한다. |
| `n_fft` | **400** | 소리를 주파수로 분해할 때 한 번에 들여다보는 샘플 개수. |
| `hop_length` | **160** | 그 분석 창을 얼마나 촘촘히 이동시키며 반복할지. |
| `max_audio_seconds` | **8.0초** | 발화가 이보다 길면 앞 8초까지만 사용. |
| `backbone_dropout` | **0.2** | 음성 처리기(TemporalConvFrontend) 내부 드롭아웃. |
| 운율(prosody) 벡터 | **10차원** | 멜 스펙트로그램과 별개로, 피치(음높이)·jitter(떨림)·shimmer(진폭 흔들림) 등을 발화 전체 기준 숫자 10개로 요약해서 따로 추출 — 이건 시간 순서가 있는 시퀀스가 아니라 발화 하나당 고정된 벡터 하나라서, 크로스 어텐션이 아니라 "게이트"(4.5절)로 결합된다. |

### 4.4 영상(얼굴) 처리

| 설정 | 값 | 무슨 뜻인가 |
|---|---|---|
| 사전학습 모델 | **MobileFaceNet**(`emotiefflib` 패키지의 `mbf_va_mtl`) | 얼굴 인식 + 감정(valence-arousal) 예측을 함께 훈련받고 온 모델. 얼굴 사진 한 장을 넣으면 512개 숫자로 된 벡터가 나온다. |
| `face_size` | **112 × 112 픽셀** | 얼굴 크롭 이미지 크기. 이 백본이 원래 이 해상도로 사전학습돼 있어서, 리사이즈로 인한 화질 손실이 없다. |
| `visual_freeze_layers` | **9** (0보다 크면 전체 동결) | MobileFaceNet 백본 전체를 고정하고, 그 위에 얹은 작은 변환(512→256차원)만 훈련시킨다. |
| `visual_cnn_dropout` | **0.15** | 그 512→256 변환 사이에 적용하는 드롭아웃. |
| 프레임 수 | 추출 시 최대 **24장**, 학습 시 최대 **32장** | 발화 구간에서 얼굴 프레임을 뽑아 저장할 때 상한 24장, 학습 배치로 묶을 때 32장 넘으면 균등 간격으로 샘플링. 부족하면 0으로 채움(패딩). |

### 4.5 융합 (크로스 어텐션)

세 전문가의 벡터(256차원으로 통일된 상태)를 두 단계로 섞는다.

1. **1단계**: 음성 ↔ 텍스트가 서로를 참고해서 정보를 보강.
2. **2단계**: 영상 ↔ (음성+텍스트 결합 결과)가 다시 서로를 참고.

이 과정에 크로스 어텐션 블록이 총 **4개** 쓰인다. 각 블록의 드롭아웃(`cross_attn_dropout`)은 **0.2**.

그 다음, 운율(prosody) 10차원 벡터가 **게이트(gate)** 역할을 한다 — "지금 목소리 떨림이 큰 상황이면 음성 정보에 더 가중치를 주자"처럼, 운율 값에 따라 각 모달리티 정보를 얼마나 반영할지 스스로 조절하는 작은 장치다.

### 4.6 최종 분류기

크로스 어텐션을 거친 결과와, 각 모달리티 백본의 원본 출력을 평균 낸 값(mean-pooling)을 **이어붙여서(concat)** 하나의 큰 벡터로 만든 뒤, 이걸 신경망 몇 겹(분류기)에 통과시켜 최종적으로 7개 감정 중 하나에 대한 확률을 낸다. 이 분류기의 드롭아웃(`classifier_dropout`)은 **0.35** — 모델 전체에서 가장 높은 값이다. 정보가 가장 좁게 모이는 마지막 병목 지점이라 가장 세게 규제한다.

### 4.7 파라미터(가중치) 개수 — 실제로 코드에서 세어본 값

모델 전체는 **총 1억 2,104만 개**(121,039,367개)의 숫자(파라미터)로 이뤄져 있다. 이 중 몇 개가 실제로 "학습 중에 움직이는지"(trainable)는 `text_freeze_layers` 설정에 따라 완전히 달라진다 — 아래는 v6 방식(8, 상위 4개 층 미세조정)과 v7 방식(12, 완전 동결)을 각각 실제로 계산한 값이다.

| 구성 요소 | 전체 파라미터 | v6 방식 학습 가능 개수 | v7 방식 학습 가능 개수 |
|---|---|---|---|
| 음성(`audio_backbone`) | 1,838,080개 | 1,838,080개(전부) | 1,838,080개(전부) |
| 영상(`visual_backbone`) | 4,164,096개 | 2,104,576개 | 2,104,576개 |
| 텍스트(`text_backbone`, BERT+투영) | 110,814,208개 | 28,548,352개 | **196,864개** |
| 융합(`fusion`, 크로스 어텐션 4블록) | 3,159,040개 | 3,159,040개(전부) | 3,159,040개(전부) |
| 분류기(`classifier`) | 790,535개 | 790,535개(전부) | 790,535개(전부) |
| **모델 전체 합계** | **121,039,367개** | **36,713,991개** | **8,362,503개** |

즉 v7처럼 BERT를 완전히 동결하면, **실제로 학습 중에 움직이는 파라미터 수가 3,671만 개에서 836만 개로 약 4.4분의 1로 줄어든다.** "움직일 수 있는 손잡이의 개수 자체가 확 줄어드니, 79,601개 데이터로 외워버릴 여지도 그만큼 줄어든다"는 게 v7에서 과적합이 완화된 이유를 파라미터 개수로 직접 보여주는 숫자다. (참고: BERT 전체(110,814,208개)가 이미 전체 모델의 약 91.6%를 차지한다 — 텍스트 전문가 하나가 나머지 두 전문가+융합+분류기를 합친 것보다 훨씬 크다.)

## 5. 학습(training) 설정 — 정확한 수치 전부

### 5.1 데이터

- 전체 **79,601개** 발화. **train 55,920개 / val(검증) 11,840개 / test(평가) 11,841개**로 분할(약 70% / 15% / 15%).
- 분할 기준: 발화 단위가 아니라 **clip_id(장면) 단위**로 통째로 나눔 — 같은 장면의 여러 발화가 train과 test에 걸쳐 흩어지면 답을 미리 살짝 봐버리는 문제(정보 누수)가 생기기 때문. 분할 스크립트(`split_manifest.py`) 기본값은 `val-ratio=0.15`, `test-ratio=0.15`, `seed=42`.
  - ⚠️ **이 방식으로는 충분하지 않다는 것이 나중에 밝혀졌다** — 장면은 분리했지만 **같은 사람**은 분리되지 않았다. 자세한 내용은 8.5절 참고. 아래의 모든 정확도 수치는 이 한계를 감안하고 읽어야 한다.
- `batch_size` = **128** (한 번에 128개 발화씩 묶어서 학습)
- `num_workers` = **8** (데이터 준비를 8개 프로세스가 동시에 함, 학습 속도용 설정)

**데이터가 79,601개까지 오게 된 과정(정확한 숫자)**: 원본 AI Hub 배치 중 `5201-5600`(400클립) 배치 하나가 통째로 소실된 걸 발견해 재다운로드로 복구 — 해당 구간 발화 5,639개 중 **5,637개(99.96%) 복구**, 끝내 얼굴 검출 자체가 실패한 **520개(전체의 0.65%)만 영구 손실**로 남음. 그 외 인코딩이 다른(CP949) JSON 파일 **2개 클립**은 별도 처리 없이 보류 중.

**테스트셋(11,841개) 클래스별 분포**(실제 평가 결과의 confusion matrix 합계 기준):

| 감정 | 개수 | 비율 |
|---|---|---|
| 혐오(disgust) | 3,150 | 26.6% |
| 행복(happy) | 2,433 | 20.5% |
| 놀람(surprise) | 1,691 | 14.3% |
| 중립(neutral) | 1,483 | 12.5% |
| 슬픔(sad) | 1,184 | 10.0% |
| 분노(angry) | 1,086 | 9.2% |
| 공포(fear) | 814 | 6.9% |

가장 많은 혐오(3,150개)와 가장 적은 공포(814개)의 비율은 **약 3.87배** — 이 정도 불균형을 완화하기 위해 5.2절의 `class_weights`를 쓴다.

### 5.2 Loss function (모델이 "얼마나 틀렸는지" 계산하는 방법)

**학습용 공식**: `CrossEntropyLoss(weight=class_weights, label_smoothing=0.1)`

- **`class_weights`**: 감정 클래스마다 데이터 개수가 다르다(예: 혐오 3,150개 vs 공포 814개, 테스트셋 기준). 데이터가 적은 클래스를 틀렸을 때 벌점을 더 크게 주기 위해, 클래스별로 `1/√(그 클래스 데이터 개수)`를 가중치로 준다. 그냥 `1/개수`를 쓰면 너무 세게 보정돼서 학습이 불안정해졌던 적이 있어(과거 실험), 완만한 제곱근 버전을 쓴다. 전체 가중치 평균이 1이 되도록 정규화해서 loss 전체 스케일이 과하게 커지지 않게 한다.
- **`label_smoothing=0.1`**: 정답 클래스에 100% 확신(목표 확률 1.0)을 주는 대신, **정답 클래스는 91.4%**(계산: `1 - 0.1 + 0.1/7`), **나머지 6개 클래스는 각각 1.43%**(`0.1/7`)를 목표로 준다. 감정 라벨 자체가 애매한 경우가 많아서, 모델이 지나치게 자신만만해지는 걸 막는다.

**평가(검증·테스트)용 공식**: 가중치·smoothing이 없는 **순수 `CrossEntropyLoss`**. 학습 트릭이 섞이지 않은, 실제 데이터 분포 그대로의 지표를 보기 위해서다.

### 5.3 옵티마이저 (가중치를 얼마나/어떻게 업데이트할지)

- **AdamW**, `weight_decay` = **0.05** (가중치가 너무 커지지 않게 매 스텝마다 살짝씩 줄이는 정규화 — 값이 클수록 더 세게 억제)
- **학습률(lr, learning rate)** — "한 번에 얼마나 크게 수정할지":
  - v1~v7: 모델 전체에 **단일 lr = 2e-4(0.0002)**
  - **v8부터**: 파라미터를 두 그룹으로 나눔 — **BERT의 미세조정 대상 상위 층은 `bert_lr = 2e-5(0.00002)`**(원래 그룹보다 10배 낮음, 사전학습 지식을 급격히 안 흔들기 위해), **나머지 전부(크로스 어텐션·분류기·음성/영상 프론트엔드)는 기존 그대로 2e-4**
- AdamW의 세부 값(`betas=(0.9, 0.999)`, `eps=1e-8`)은 파이토치 기본값 그대로 사용(따로 손대지 않음)

### 5.4 학습률 스케줄러 (학습 중 lr을 자동으로 낮추는 규칙)

`ReduceLROnPlateau`: **검증 loss(val_loss)가 3에폭(patience=3) 연속 좋아지지 않으면, lr을 절반(factor=0.5)으로 줄인다.** 이걸 반복하다가 lr이 **1e-6(min_lr)** 밑으로는 더 내려가지 않는다. lr이 바닥을 찍고도 개선이 없으면 그 시점에 학습을 수동으로 종료한다(v1~v7 전부 이 기준으로 멈췄음).

> 세부 사항 하나: v8처럼 파라미터 그룹이 2개면, 이 규칙은 두 그룹에 **같은 배수**로 동시에 적용된다. 그런데 시작값이 다르므로(2e-4 vs 2e-5), `bert_lr` 쪽이 먼저 1e-6 바닥에 도달하고, 그 뒤로도 메인 lr은 계속 더 내려갈 수 있다 — 학습이 길어지면 BERT 쪽 업데이트가 먼저 사실상 멈추는 비대칭이 생긴다.

### 5.5 과적합 방지(정규화) 장치 — 전체 총정리

"과적합"이란 모델이 학습 데이터를 이해하지 않고 통째로 암기해버리는 현상이다. 이를 막기 위한 장치를 전부 모으면:

| 장치 | 값 | 어디에 적용되나 |
|---|---|---|
| `weight_decay` | 0.05 | 옵티마이저(전체 파라미터) |
| `label_smoothing` | 0.1 | 학습용 loss |
| 클래스 가중치 | `1/√count` | 학습용 loss |
| `text_dropout` | 0.2 | BERT 내부 |
| `backbone_dropout` | 0.2 | 음성·영상 프론트엔드 |
| `visual_cnn_dropout` | 0.15 | 영상 백본→투영 사이 |
| `cross_attn_dropout` | 0.2 | 크로스 어텐션 4블록 |
| `classifier_dropout` | 0.35 | 최종 분류기(가장 강함) |
| `modality_dropout_prob` | 0.25 | 학습 배치의 샘플마다 25% 확률로 세 모달리티(음성/영상/텍스트) 중 하나를 통째로 지움(0으로 만듦). 계산해보면 배치 크기 128개 기준 **평균 32개 샘플**(128×0.25)에서 어떤 모달리티든 하나가 꺼진 채로 학습된다는 뜻. 음성이 걸리면 멜 스펙트로그램과 운율 벡터 둘 다 지움. 텍스트가 걸리면 BERT가 최소 1토큰은 필요해서 토큰 1개만 남겨둠. 목적: 텍스트(가장 강한 신호)에만 의존하지 않게 강제. |
| `text_freeze_layers` | 8 또는 12 | BERT — 사전학습 지식 보존 |
| `visual_freeze_layers` | 9(동결) | 영상 백본 — 사전학습 지식 보존 |
| gradient clipping (신규) | `max_norm=1.0` | 매 학습 스텝, 역전파 직후 — 가끔 튀는 gradient(수정 폭)가 학습을 통째로 흔들지 않게 크기를 제한 |
| `cross_attn_drop_path` (v9 신규) | 0.1 | 크로스 어텐션 4블록 — 드롭아웃이 "뉴런 일부"를 끄는 것과 달리, 이건 학습 중 **샘플 단위로 그 블록을 통째로 건너뛴다**(10% 확률). 건너뛴 샘플은 그 블록이 없는 것처럼 계산된다. v1~v8은 0.0(미적용)이었다. |

### 5.6 재현성 / 안정성 (최근 추가)

- **`seed=42`**(신규): `torch.manual_seed`, `random.seed`, `torch.cuda.manual_seed_all`을 학습 시작 전에 고정. 원래는 이게 전혀 없어서, 같은 설정으로 두 번 돌려도 초기 가중치·데이터 셔플 순서가 매번 달라졌다 — 버전 간 0.5~2%p 차이가 "설정 변경 효과"인지 "그냥 실행 운"인지 구분이 안 됐던 문제를 줄이기 위함.
- 체크포인트: **20에폭마다** 스냅샷 저장 + **검증 정확도(val_accuracy)가 갱신될 때마다** "최고 기록" 파일 별도 저장 → 최종 평가는 항상 이 "최고 기록" 파일로 함.

## 6. 버전(v1~v8)별로 정확히 뭐가 달랐는가

| 버전 | 데이터 | text_freeze_layers | bert_lr | 그 외 바뀐 것 | val_acc(최고) | test_acc |
|---|---|---|---|---|---|---|
| v1 | 400개 | - | - | 클래스 가중치 없음 | 31.4%(20에폭) | 27.4% |
| v2 | 80,122개 | - | - | `1/√count` 가중치만 추가 | 32.2%(12에폭) | - |
| v3 | 80,122개 | 8 | 없음(단일 lr) | dropout·weight_decay·lr스케줄러 도입 | 41.16%(10에폭) | - |
| v4 | 80,122개 | 8 | 없음(단일 lr) | v3 + 운율 z-score 정규화 | 42.54%(4에폭) | 41.08% |
| v5 | 79,601개 | 8 | 없음(단일 lr) | v4 + 얼굴 크롭 버그 수정(4.4절) | 44.74%(6에폭) | 44.13% |
| v6 | 79,601개 | 8 | 없음(단일 lr) | v5 + 경멸→혐오 라벨 통합(8→7클래스) | 47.18%(5에폭) | 46.29% |
| v7 | 79,601개 | **12(전체 동결)** | 해당없음 | v6 + BERT 완전 동결 | 48.27%(13에폭) | 46.74% |
| v8 | 79,601개 | 8 | **2e-5** | v6 + BERT 차등 학습률 | 48.08%(8에폭) | **47.22%**(단일 최고) |
| v9 | 79,601개 | 12 | 해당없음 | v7 + 크로스어텐션 DropPath 0.1 | 48.69%(12에폭) | 47.52% |
| **v10** | 79,601개 | 12 | 해당없음 | v9 레시피 + **화자 독립 분할** | 45.91%(11에폭) | **44.15%** ← 진짜 성능 |

**v9(진행 중)에서 새로 바뀐 것**: v7 설정(BERT 완전 동결)을 그대로 기준으로 삼고, 크로스 어텐션 4블록에 **DropPath 0.1**을 추가했다(5.5절 표 마지막 줄). v7에서도 23.4%p 남아있던 암기 격차의 다음 원인으로 이 융합 모듈(316만 파라미터 — BERT를 얼린 뒤 남은 학습 대상 895만 개 중 가장 큰 덩어리인데 지금까지 드롭아웃 외 규제가 전혀 없었음)을 지목했기 때문이다. 부수적으로 **스냅샷 저장 간격을 20에폭 → 5에폭으로 좁혔다** — v7·v8 모두 최고점이 8~13에폭인데 20 간격으로는 그 근방 저장본을 하나도 못 잡아서 SWA(아래)가 실패했던 문제 때문이다.

**설정상 에폭 상한(`epochs`)은 100이지만, 실제로 100까지 간 버전은 하나도 없다** — 전부 5.4절 기준(lr이 바닥까지 떨어지고도 개선 없음)으로 그 전에 수동 종료했다. 실제 학습이 멈춘 시점(마지막으로 기록된 에폭):

| 버전 | v1 | v2 | v3 | v4 | v5 | v6 | v7 | v8 |
|---|---|---|---|---|---|---|---|---|
| 멈춘 에폭 | 30 | 21 | 38 | 70 | 45 | 65 | 63 | 31 |

**v8 결과(31에폭에서 종료)**: 최고 val_acc 48.08%(8에폭)로 v7(48.27%)에 0.19%p 못 미쳤지만, **test에서는 47.22%로 v7(46.74%)을 0.48%p 앞섰다** — val과 test에서 순위가 뒤집힌 셈이라 정확도만으로는 우열을 가리기 어렵다.

다만 **실무적으로는 v7(완전 동결)이 낫다**고 판단해 이후 실험의 기준으로 삼았다. 이유는 두 가지다:
1. **학습해야 할 파라미터가 4.4배 적다** — v7은 836만 개, v8은 3,671만 개. 같은 성능이면 적게 움직이는 쪽이 안전하다.
2. **암기(과적합) 속도가 훨씬 느리다** — v8은 31에폭 만에 train/val 격차가 29.0%p까지 벌어졌고 그 시점에도 계속 커지는 중이었다. v7은 63에폭에 걸쳐 23.4%p에서 멈췄다.

대신 v8은 v7과 **잘 맞히는 감정이 서로 다르다**는 게 확인됐다 — v8은 중립(neutral) recall이 0.43으로 v7(0.35)보다 훨씬 좋고, 반대로 공포(fear)는 0.21로 v7(0.32)보다 나쁘다. 이 상보성이 아래 앙상블에서 그대로 효과로 이어졌다.

**재학습 없이 기존 체크포인트만 조합한 실험(A단계) — 정확한 수치**:
- **SWA(체크포인트 가중치 평균) 실패**: v7의 20에폭 간격 스냅샷 3개(epoch40 val 45.73%, epoch60 val 45.68%, best=13에폭 val 48.27%)를 파라미터별로 평균 → test_acc **46.52%**, weighted F1 **0.4628** (v7 단독 46.74%/0.4637보다 낮아짐 — 저장 간격이 성겨서 최고점에서 멀어진 스냅샷이 섞였기 때문)
- **앙상블(v6+v7 확률 평균) 성공**: test_acc **47.95%**, weighted F1 **0.4741** — v7 단독 대비 +1.21%p
- **3중 앙상블(v6+v7+v8) — 현재 전체 최고 기록**: test_acc **48.50%**, weighted F1 **0.4814**, macro F1 **0.45**. 두 개일 때(47.95%)보다 +0.55%p 더 올랐고, 중요한 건 **macro F1도 0.44→0.45로 올랐다는 점** — 데이터 많은 감정 덕만 본 게 아니라 소수 감정까지 고르게 개선됐다는 뜻이다.

## 8. 지금 점검하고 있는 것들 — 정확한 기준

큰 방향을 찾는 동시에, 기본기를 다시 점검하는 중이다.

1. **Gradient clipping** (`max_norm=1.0`, 5.5절): 지금까지 전혀 없었음 — 추가함.
2. **Seed 고정** (`seed=42`, 5.6절): 지금까지 전혀 없었음 — 추가함. 버전 간 비교의 신뢰도를 높이기 위함.
3. **데이터 품질 진단 — 결과: 문제없음.** 학습 데이터에 최소 품질 기준(텍스트 최소 길이, 얼굴 프레임 최소 장수 등)이 코드상 전혀 없다는 걸 발견해서 실제 분포를 조사했다. 결과는 우려보다 훨씬 깨끗했다:

| 항목 | 최솟값 | 하위 1% | 중앙값 | 부실한 샘플 비율 |
|---|---|---|---|---|
| 텍스트 길이 | 1자 | 2자 | 22자 | 3자 미만이 1.78% |
| 얼굴 프레임 수 | 1장 | 4장 | 26장 | 2장 미만이 0.28% |
| 오디오 길이 | 0.56초 | 0.88초 | 3.71초 | 1초 미만이 1.86% |

   짧은 텍스트도 "왜?", "네.", "어!"처럼 **실제 대화에서 정상적으로 나오는 발화**라 걸러낼 이유가 없다고 판단해 필터링은 하지 않기로 했다.

   **여기서 뜻밖의 발견**: 가장 많이 반복되는 텍스트 상위 10개가 전부 이런 짧은 발화다("왜?" 188회, "네." 136회). 이건 **텍스트만으로는 감정을 절대 구분할 수 없는 샘플**이다 — 화나서 "왜?"인지 놀라서 "왜?"인지는 목소리와 표정에만 있으니까. 즉 **이 부분집합에서의 정확도가 곧 "음성·영상 전문가가 실제로 일을 하고 있는가"의 직접적인 증거**가 된다. 나중에 따로 떼서 평가해볼 가치가 있는 지표를 하나 얻은 셈이다.

4. **화자(배우) 독립성 확인 — 결과: ⚠️ 문제 발견.** 아래 별도 항목(8.5절)에서 자세히 다룬다.

### 8.5 ⚠️ 가장 중요한 발견 — 시험 문제에 정답이 새고 있었다 (화자 누수)

**한 줄 요약**: 데이터를 나눌 때 "같은 장면이 겹치지 않게" 나눴는데, **"같은 사람이 겹치지 않게"는 나누지 못했다**는 걸 뒤늦게 발견했다. 이 프로젝트에서 얼굴 크롭 버그(4번째 버전) 다음으로 영향이 큰 문제다.

#### 무엇이 문제인가 — 비유로

시험 준비를 이렇게 했다고 생각해보자. 문제집 100장을 무작위로 섞어서 70장은 공부용, 30장은 시험용으로 나눴다. 문제가 겹치지 않으니 공정해 보인다. **그런데 알고 보니 그 문제집은 "김철수의 문제 유형", "이영희의 문제 유형"처럼 사람별로 묶여 있었고, 무작위로 섞으면서 같은 사람의 문제가 공부용과 시험용 양쪽에 들어가버린 것이다.**

이러면 학생은 "문제 푸는 법"이 아니라 **"김철수는 이런 식으로 문제를 낸다"를 외워서** 시험을 잘 볼 수 있다. 하지만 처음 보는 출제자의 문제를 만나면 무너진다.

우리 모델도 똑같은 상황이었다. **"이 사람은 화날 때 이런 표정, 이런 목소리를 낸다"를 외워도 시험(test) 점수를 받을 수 있었다.**

#### 어떻게 발견했나 — 추적 과정

데이터 파일 이름은 `1_1_31_131` 같은 형식인데, 앞의 두 숫자가 각각 (장면 번호, 인물 번호)다. 지금까지 **장면 번호**만 보고 데이터를 나눠왔는데, **인물 번호가 정확히 뭘 뜻하는지 한 번도 확인한 적이 없다**는 걸 깨닫고 조사했다.

| 확인한 것 | 결과 | 무슨 뜻인가 |
|---|---|---|
| 시험용 데이터의 인물 수 | 278명 | — |
| 그중 학습용에도 있는 인물 | **278명 (전원)** | **처음 보는 사람이 단 한 명도 없음** |
| 인물 번호 `114`가 나오는 장면들 | 2241~2280 (정확히 연속) | 특정 구간에만 등장 |
| 인물 번호 `90`이 나오는 장면들 | 1761~1800 (정확히 연속) | 역시 특정 구간, 위와 안 겹침 |

마지막 두 줄이 결정적이다. 인물 번호마다 **정확히 40개짜리 연속 구간**에만 등장하고 구간끼리 겹치지 않는다는 건, 이 데이터가 **40개 장면 단위(원본 영상 1편)로 묶여 있고 인물 번호는 그 영상에 나오는 특정 배우에게 붙은 고유 번호**라는 뜻이다. 즉 `인물 114`는 **실제로 존재하는 한 사람**이다.

그리고 장면을 무작위로 섞어 나누면, 그 사람이 나오는 40개 장면이 학습용·검증용·시험용에 흩어진다 → **같은 사람이 세 곳 모두에 들어간다.**

#### 왜 미리 못 잡았나

두 가지가 겹쳤다:

1. **설계 문서에는 제대로 적혀 있었다.** "화자가 학습/검증/시험 중 한 곳에만 등장해야 한다"고 명시돼 있었는데, 실제 코드는 장면 단위로만 나누고 있었다. **설계와 구현이 어긋난 것을 아무도 대조해보지 않았다.**
2. **예전 점검이 안심시켜버렸다.** 이전에 "화자 편향"을 점검한 기록이 있어서 괜찮은 줄 알았는데, 다시 확인해보니 그건 **"특정 사람이 특정 감정에만 치우쳐 있는가"**를 본 것이었고, **"같은 사람이 양쪽에 들어갔는가"**는 검사한 적이 없었다. 이름이 비슷한 다른 검사였다.

#### 그래서 지금까지 한 게 헛수고인가? — 아니다

중요한 구분이 있다:

- **절대 수치의 해석은 바뀐다.** "48.50%"는 "이미 만나본 사람 기준 48.50%"로 다시 읽어야 한다. 처음 보는 사람 기준으로는 더 낮을 것이다.
- **하지만 버전 간 비교는 그대로 유효하다.** v5(얼굴 버그 수정)·v6(감정 통합)·v7(BERT 동결) 등은 **전부 똑같은 조건에서 비교**했으므로, "이 변경이 성능을 올렸다"는 결론 자체는 흔들리지 않는다.

비유하자면, 모든 학생이 같은 방식으로 부풀려진 점수를 받았으므로 **누가 더 잘했는지 순위는 여전히 맞다**. 다만 "80점"이라는 절대 점수의 의미가 달랐던 것이다.

#### 어떻게 고칠 것인가

다행히 비용이 크지 않다. 무거운 전처리 결과(음성·표정 특징)는 발화 단위로 저장돼 있어서 **나누는 방식과 무관하게 그대로 재사용**된다. 즉 다시 나누고 다시 학습만 하면 되고, 약 7시간이면 끝난다.

1. **40장면 블록(원본 영상) 단위로 다시 나눈다** — 이러면 사람뿐 아니라 배경·조명까지 함께 분리된다
2. 기존 데이터 분할은 백업해둔다 (지금까지 결과의 재현성 유지)
3. 새 분할로 재학습
4. **두 숫자를 모두 보고한다** — "이미 만나본 사람 기준 48.50% / 처음 보는 사람 기준 XX%"

4번이 핵심이다. 이 차이가 곧 **"사람을 외워서 얻었던 점수"의 크기**이고, 그 자체로 기록할 가치가 있는 정직한 수치다.

#### 결과 — 얼마나 부풀려져 있었나

재분할 후 똑같은 설정으로 다시 학습시켰다(v10). 결과가 나왔다.

![화자 누수를 제거하면 무엇이 달라지는가](assets/speaker_leakage_effect.png)

| | v9 (이미 만나본 사람) | **v10 (처음 보는 사람)** |
|---|---|---|
| 정확도 | 47.52% | **44.15%** |
| 찍기만 해도 나오는 점수 | 23.86% | 27.00% |
| **모델이 실제로 벌어들인 몫** | **+23.66%p** | **+17.15%p** |

**겉으로는 3.37%p만 떨어진 것처럼 보이지만, 실질적으로는 6.51%p가 사라졌다.** 새 시험지가 "찍기만 해도" 3%p 더 잘 나오는 구성이었기 때문이다. 그래서 단순 정확도가 아니라 **"찍기보다 얼마나 잘하나"**로 비교해야 공정하다.

#### 어느 감정이 무너졌나 — 납득이 되는 패턴

| 감정 | 변화 |
|---|---|
| 행복 | −0.01 (거의 그대로) |
| 놀람 | −0.02 |
| 분노 | −0.03 |
| 혐오·슬픔 | −0.04 |
| **공포** | **−0.06** |
| **중립** | **−0.07** |

**활짝 웃는 표정이나 눈이 커지는 반응은 사람이 달라도 비슷하다.** 그래서 행복·놀람은 거의 안 떨어졌다.

반면 **"이 사람 특유의 무표정", "이 사람이 긴장했을 때의 목소리"는 사람마다 천차만별이다.** 중립과 공포가 가장 크게 무너진 건, 그동안 이 부분을 **사람별로 외워서** 버티고 있었다는 뜻이다.

이 패턴 자체가 진단이 옳았다는 증거이기도 하다 — 시험지가 그냥 어려워졌다면 모든 감정이 고르게 떨어졌을 텐데, **개인차에 기대던 감정만 골라서** 무너졌기 때문이다.

#### 그래서 지금 우리 모델의 진짜 성능은

**44.15%** — 처음 보는 사람의 감정을 맞히는 능력이다. 이게 로봇이 실제로 마주할 조건이고, 앞으로 이 숫자를 기준으로 삼는다.

목표(80~85%)까지의 거리는 이전에 보이던 것보다 훨씬 멀다. 하지만 **이제야 제대로 된 출발선에 섰다** — 앞으로 올라가는 숫자는 진짜 실력이다.

### 8.6 음성 담당을 교체하다 — 지금까지 중 가장 큰 개선

2장에서 "세 전문가 중 음성 전문가만 사전학습 없이 처음부터 배우고 있다"고 했다. 화자 독립 조건이 되면서 이게 더 중요해졌다 — **사람을 외워서 버틸 수 없게 됐으니, 각 전문가 자체의 실력이 그만큼 더 필요해졌기 때문**이다.

그래서 음성도 이미 훈련된 전문가(**wav2vec2**, 53개 언어의 방대한 음성으로 사전학습된 모델)로 교체해봤다.

#### 조사에서 알게 된 것 — 아무 모델이나 쓰면 안 된다

"한국어 음성 모델"로 검색하면 나오는 것들은 대부분 **음성인식(받아쓰기)용으로 추가 훈련된 모델**이다. 그런데 연구를 찾아보니 이런 모델은 감정인식에 **오히려 나쁘다**.

이유가 명쾌하다. 받아쓰기의 목표는 "누가 어떤 감정으로 말했든 **같은 글자**를 뽑는 것"이다. 즉 화자와 감정 정보를 **일부러 지우도록** 훈련된다. 우리에게 필요한 건 정확히 그 지워진 정보다.

그래서 받아쓰기 훈련을 거치지 않은, 순수하게 "소리의 구조"만 배운 모델을 골랐다.

#### 결과 — 공정하게 비교하기 위해 대조군을 따로 돌렸다

예전에 측정해둔 멜 방식 성적(33.14%)이 있었지만, 그건 **화자 누수가 있던 시절의 조건**이라 직접 비교할 수 없다. 8.5절에서 겪은 일이 바로 그것이었다 — 조건이 다른 숫자를 나란히 놓으면 안 된다.

그래서 **같은 데이터·같은 시작점·같은 설정에서 음성 담당만 바꿔** 다시 돌렸다.

| 음성만으로 감정 맞히기 | 정확도 | **찍기(27%)보다 얼마나 잘하나** | 걸린 시간 |
|---|---|---|---|
| 멜 (기존) | 31.74% | **+4.74%p** | 2분/회 |
| **wav2vec2** | **39.48%** | **+12.48%p** | 16분/회 |

**"찍기보다 얼마나 잘하나"가 2.6배**로 늘었다. 그동안 음성 담당은 사실상 찍는 것보다 조금 나은 수준이었는데, 이제야 제 역할을 할 수 있게 됐다.

**덤으로 얻은 확인**: 같은 멜 방식을 두 조건에서 비교하니 8.5절 결론이 다시 확인됐다 — 화자 누수를 없애자 상승폭이 9.28%p에서 4.74%p로 떨어졌다. 트리모달에서 쟀던 6.51%p와 방향이 같다.

**대가도 있다**: 8배 느려지고 모델이 172배 커진다(1.2억 → 4.4억). 로봇에 올리려면 결국 가볍게 만들어야 하는데, 이건 정확도가 목표에 가까워진 뒤에 풀 문제다.

지금은 이 교체를 **세 전문가 전체 모델에 적용해서** 다시 학습시키는 중이다.

### 8.7 이 프로젝트에서 반복해서 나온 문제 유형

지금까지 찾아낸 큰 문제들을 모아보니 공통점이 있었다. **전부 "에러 없이 잘 돌아가면서 결과만 조용히 망가뜨리는"** 종류였다.

| 무엇이 잘못됐나 | 왜 못 알아챘나 |
|---|---|
| "얼굴" 사진이 사실 몸 전체였음 | 학습은 정상 진행, 성적만 낮게 나옴 → 3번이나 다른 원인으로 오해 |
| 음성을 끄는 기능이 절반만 작동 | 로그로는 구분 불가 |
| 같은 사람이 연습문제와 시험지 양쪽에 | 오히려 성적이 **좋게** 나옴 |
| 새 모델을 옛날 시험지로 평가 | 에러 없이 그럴듯한 숫자가 나옴 |
| 실험 A의 결과 파일을 실험 B가 덮어씀 | 아무 경고도 없음 |

프로그램이 **멈춰주면** 바로 알아채고 고친다. 문제는 이런 것들이 **멈추지 않는다**는 점이다. 그럴듯한 숫자가 나오니까 믿고 다음 단계로 넘어가게 된다.

#### 그래서 생긴 습관 세 가지

**① 긴 학습 전에 코드를 전부 다시 훑는다.** 7~13시간짜리를 돌리기 전 20~30분 점검으로, 두 번에 걸쳐 10건을 잡았다. 명백히 남는 장사다.

**② 설계 문서와 코드를 대조한다.** 화자 누수는 "설계서에는 하라고 적혀 있는데 코드에는 없던" 것이라, 코드만 아무리 봐도 못 찾을 종류였다.

**③ 비교하려면 딱 하나만 바꾼다.** 이번에도 음성 모델을 교체하면서 배치 크기를 같이 바꿨다가, 1회차 결과를 보고 "이러면 뭐가 원인인지 모른다"는 걸 깨닫고 20분 만에 중단하고 다시 시작했다. 13시간을 흐린 조건으로 돌리는 것보다 낫다.

### 8.8 음성 담당 교체 결과 — 역대 최고 성적

8.6절에서 음성 담당을 wav2vec2로 바꾸기로 했고, 실제로 학습시킨 결과가 나왔다.

| | 이전(v10, 멜) | **바꾼 뒤(v11)** |
|---|---|---|
| 시험 점수 | 44.15% | **46.19%** |
| 찍기 점수(27.00%) 대비 | +17.15%p | **+19.19%p** |

**7가지 감정 중 6가지가 좋아졌고 나빠진 건 하나도 없다.** 그리고 v10이 74번 반복 학습해서 얻은 점수를 **9번 만에** 넘었다.

다만 9번째부터는 오히려 나빠지기 시작했다. 시험 점수는 46.80%에서 멈췄는데 연습 문제 점수는 계속 올라가서(54% → 66%) 격차가 두 배가 됐다. **외우기 시작한 것**이라 15번째에서 멈췄다.

두 모델을 합쳐서 쓰는 것(앙상블)도 해봤는데 46.37%로 **0.18%p밖에 안 올랐다.** 11,464문제 중 21문제 차이라 사실상 우연이다. 두 모델이 음성 담당만 다르고 나머지가 똑같아서 같은 문제에서 같이 틀리기 때문이다.

### 8.9 모델 머릿속을 열어봤다 — 감정보다 "누구인지"를 3배 더 담고 있었다

"모델이 사람을 외우는 것 같다"는 건 그동안 추측이었다. 이번에 측정했다.

**방법**: 모델이 발화 하나마다 만드는 **512개 숫자 요약**을 꺼내서, 그것만 주고 두 가지를 맞혀보게 했다.

- **감정**을 맞혀봐 → 25% 수준
- **누가/어느 촬영분인지** 맞혀봐 → **75% 수준**

**감정 판단하라고 만든 요약인데 "누구인지"가 3배 진하게 적혀 있었다.**

재미있는 건 **글자 담당도 화자를 69% 맞혔다**는 점이다. 전사문에는 목소리도 얼굴도 없는데 어떻게 사람을 알아볼까? 답은 **"사람"이 아니기 때문**이다. 이 데이터는 한 사람 = 드라마 한 편이라, 모델이 외운 건 사람이 아니라 **"어느 촬영 회차인가"**다. 배경·조명·말투·주제가 통째로 묶여 있다.

**한 사람 안에서만 감정을 구분하게 하면** 얼굴·목소리·배경이 고정되니 남는 차이는 감정뿐이다. 이 조건에서 감정 신호가 **2.26배**가 됐다. 화자 차이가 실제로 방해하고 있었다는 뜻이다.

그런데 **각 사람의 평균을 빼는 방식으로는 전혀 나아지지 않았다**(오히려 −0.15%p). 이게 중요하다 — 사람마다 벡터가 통째로 밀려 있는 게 아니라, **감정을 표현하는 방향 자체가 다르다**는 뜻이다. 어떤 사람은 화나면 목소리가 커지고 어떤 사람은 오히려 조용해진다. 평균을 옮겨서 맞출 수 있는 게 아니다.

### 8.10 정답지를 열어봤다 — 왜 어려운지 알아냈다

"목표 80%가 애초에 가능한 숫자인가"를 추측이 아니라 데이터로 쟀다.

**AI Hub 원본에는 감정 정답이 네 개 들어 있었다.** 영상만 보고 매긴 것, 소리만 듣고 매긴 것, 글자만 읽고 매긴 것, 그리고 전부 종합한 것(우리가 쓰는 정답).

5,637개를 전부 세어봤다:

| 정답 종류 | 우리 정답과 일치 |
|---|---|
| **소리로 매긴 것** | **77.35%** |
| **영상으로 매긴 것** | **41.69%** |
| **글자로 매긴 것** | **30.87%** |
| 넷 다 일치 | **10.20%** |

*(이 표는 전체의 7%인 5,637개 기준이다. 이후 전체 79,601개로 다시 세어보니 소리 73~74% / 영상 40~41% / 텍스트 34~35%로, 크기 순서와 결론은 같았다.)*

**넷이 다 같은 경우가 10%뿐이다.** 사람끼리도 90% 가까이 의견이 갈린다는 뜻이다.

그리고 이게 **우리 모델이 안 되는 진짜 이유**였다.

가장 극단적인 예가 "중립"이다. 정답이 중립인 발화 403개 중, **영상만 본 사람도 중립이라고 한 건 6.9%(28개)뿐**이다. 나머지 93%는 화면상으로는 다른 감정으로 보였다.

그런데 우리 모델은 영상 담당에게 이렇게 요구해왔다:

> "이 얼굴을 보고 **중립**이라고 답해라."

화면에 그 답의 근거가 93% 확률로 없다. 근거가 없는데 정답을 맞히라고 하면 방법은 하나뿐이다 — **외우는 것**. 그래서 8.9절에서 본 것처럼 촬영 맥락을 외우고 있었던 거다.

**어디를 고쳐야 하는지도 나왔다:**

| 담당 | 현재 | 최대 가능 | 남은 여지 |
|---|---|---|---|
| 영상 | 35.59% | 41.69% | **6.10%p** |
| **소리** | 39.48% | 77.35% | **37.87%p** |

**영상은 이미 한계에 가깝다.** 백본을 세 번이나 갈아치우며 가장 오래 붙잡고 있던 곳인데 더 얻을 게 없다. **소리에 6배의 여지가 있고, 이번에 처음 제대로 손댔다.**

그리고 **목표 80%는 불가능한 숫자가 아니다.** 정답의 77%가 소리로 결정된다면, 소리를 사람만큼 잘 듣는 모델은 77%까지 갈 수 있다.

### 8.11 기존 로봇 코드를 점검했다

이 프로젝트의 최종 목적지인 기존 로봇 코드를 봤다. 기술적 판단은 나쁘지 않았는데, **화면에 사실이 아닌 게 표시되고 있었다.**

- **신뢰도 표시가 실제로는 안 쓰인다.** 화면에 "시각 0.50 / 음성 0.30 / 글자 0.20"이 뜨지만, 계산해보니 **완전한 암흑에서만** 글자를 쓴다. 음성 비중은 표시만 되고 판단에 **한 번도** 안 쓰인다.
- **피로도가 10초 만에 최대가 된다.** 조금만 움직여도 9.5초면 100점이 된다. 눈금이 100배쯤 어긋나 있다.
- **설명서에 없는 기능이 적혀 있다.** "웃으면 에너지 +0.3" 같은 규칙이 문서에 있는데 코드에는 그런 게 0줄이다.
- **모델이 안 떠 있어도 "중립 100%"가 뜬다.** 로딩에 실패해도 조용히 넘어가게 돼 있었다.

그리고 거기 들어있던 표정 인식 모델(`emotion_model.h5`)을 우리 데이터로 실제로 재봤다:

| | 점수 |
|---|---|
| 그 모델 | **17.55%** |
| 무조건 "혐오"라고만 찍기 | 26.24% |

**찍는 것보다 못하다.** 644개 내내 "혐오"와 "놀람"을 **한 번도** 예측하지 않았다. 그런데 혐오는 우리 데이터에서 가장 많은 감정(26%)이다.

이건 그 모델이 잘못 만들어져서가 아니라 **다른 문제를 푸는 모델**이기 때문이다. 서양인 웹 사진으로 배운 모델이라 한국 드라마 장면에는 안 맞는다. 우리 트리모달 모델(46.19%)로 교체해야 한다.

### 8.12 두 가지를 시도했고 둘 다 실패했다

8.10절에서 알아낸 것("정답의 74%는 소리로 정해지는데 영상 담당은 화면에 없는 답을 강요받는다")을 근거로 두 가지를 고쳐봤다.

**시도 1 — 소리 담당의 "귀 위치"를 바꾸기**

wav2vec2는 24층으로 되어 있고, 어느 층에서 정보를 꺼낼지 정해야 한다. 미리 재본 결과 24층이 12층보다 감정 정보가 훨씬 많았다. 그래서 바꿔서 학습시켰다.

**결과: 더 나빠졌다.** (최고 46.80% → 45.35%)

미리 잰 것과 실제 학습이 반대로 나왔다. 왜냐하면 **미리 재는 방법이 "시간 평균"을 보기 때문**이다. 실제 모델은 목소리가 시간에 따라 어떻게 변하는지를 배우는데, 평균을 내면 그 변화가 지워진다. **"정보가 많다"와 "배우기 좋다"는 다른 얘기였다.**

한 가지는 좋았다 — 24층은 **외우는 속도가 절반**이었다(14번째 반복 시점 격차 22.06pt → 8.26pt). 다만 시험 점수가 따라오지 않았다. 외우기 어렵게 만들었지만 쓸 만한 신호도 적었던 셈이다.

**시도 2 — 각 담당에게 자기가 볼 수 있는 문제도 같이 주기**

영상 담당에게 "영상으로 매긴 정답"도 함께 맞히게 했다. 화면에 근거가 있는 문제니까 외울 이유가 없어질 거라 기대했다.

**초반 5번까지는 기대대로였다.** 시험 점수가 46.98%로 **역대 최고를 넘었고**(기존 46.80%), 외우는 정도도 더 적었다.

**그런데 6번째부터 뒤집혔다.** 외우는 속도가 오히려 v11보다 빨라졌고, 최종 시험 점수는 **45.22%로 오히려 낮았다.**

**왜 그랬나**: 보조 문제를 주는 게 "덜 외우게 하는 브레이크"가 아니라 **"더 빨리 배우게 하는 가속 페달"** 이었다. 문제를 3배로 주니 3배 빨리 배웠고, 그래서 3배 빨리 외웠다. 연습 문제뿐 아니라 **모의고사(val)까지 외워버려서**, 진짜 시험(test)에서 떨어졌다.

**정리하면 진단은 맞았는데 처방이 틀렸다.**

### 8.13 그래도 하나는 확실히 알아냈다

**"모의고사 점수가 가장 높을 때의 모델을 고른다"는 규칙이 옳음을 처음 확인했다.**

지금까지는 이 규칙을 화자 누수가 있던 시절에만 검증했었다. 이번에 두 시점을 나란히 재봤다:

| 어느 시점 모델? | 상태 | 진짜 시험 |
|---|---|---|
| 모의고사 최고 (5번째) | 연습 49.6 / 모의 47.0 | **45.22%** |
| 연습 점수 높음 (10번째) | 연습 약 57 / 모의 약 45 | 44.01% |

**모의고사 기준이 1.21%p 낫다.** 앞으로 이 규칙을 의심할 필요가 없다.

### 8.14 로봇 보드가 정해졌다 — 그리고 지금 모델은 못 올라간다

로봇에 넣을 보드가 **젯슨 나노**로 정해졌다. 그 위에서 **강화학습으로 걷는 것과 모터 제어도
함께** 돌아간다. 이 조건이 지금까지의 전제를 전부 다시 보게 만들었다.

**정확도가 올라도 보드에 안 올라가면 소용이 없다.**

**먼저 속도를 쟀다** (한 번도 안 재봤었다). 말 한 마디를 판단하는 데:

| | 맥북 GPU | 맥북 CPU |
|---|---:|---:|
| 목소리 담당 | 232.8ms | 456.7ms |
| 얼굴 담당 (16장) | 88.6ms | 1,292.4ms |
| 글자 담당 | 19.4ms | 48.2ms |
| 합치기 | 9.9ms | 85.2ms |
| **전체** | **0.35초** | **1.88초** |

맥북에서는 0.35초로 충분히 빠르다. **그런데 젯슨 나노는 맥북보다 훨씬 느리다.**

**메모리부터 안 맞는다.** 젯슨 나노는 **4GB를 CPU와 GPU가 나눠 쓴다.**

```
우리 모델            1.67GB
파이토치 실행에 필요   0.8GB
음성 인식(Whisper)   0.2GB
카메라·얼굴 검출      0.3GB
──────────────────────────
                    약 3GB   ← 걷기 학습이 쓸 자리가 남지 않는다
```

**그리고 걷는 게 더 중요하다.** 모터는 1000분의 1초 단위로 명령을 받아야 하는데, 감정 판단이
GPU를 몇 초씩 잡고 있으면 로봇이 비틀거린다.

#### 모델의 97.5%가 빌려온 두 덩어리다

| 부분 | 크기 | 비중 |
|---|---:|---:|
| **목소리 담당 (wav2vec2)** | 3.15억 개 | 72.2% |
| **글자 담당 (KLUE-BERT)** | 1.11억 개 | 25.3% |
| 나머지 전부 | 0.11억 개 | 2.5% |

**"하나로 합치면 되지 않나?"** — 이미 하나다. 파일도 하나(1.6GB)다. 그런데 책 세 권을 한
상자에 넣어도 무게는 그대로인 것처럼, 합쳐도 크기는 안 줄어든다.

크기를 줄이는 방법은 따로 있다:

| 방법 | 효과 |
|---|---|
| 숫자를 대충 저장(양자화) | 4배 작아짐 (417MB) — 그래도 부족 |
| 큰 모델을 작은 모델이 흉내내게(증류) | 10~40배 가능 |
| 애초에 작은 걸 씀 | 즉시. 성능 손실이 관건 |

목표는 **100MB 이하 / 0.3초 이하**다. 지금 1,667MB / 0.35초니까 **16배**를 줄여야 한다.

### 8.15 그래서 다음은 "무엇을 빼도 되나"를 재는 것

크게 줄이려면 담당 하나를 통째로 빼야 한다. 그런데 **어느 담당이 얼마나 기여하는지 한 번도
안 재봤다.**

특히 **글자 담당을 빼면 두 가지가 같이 사라진다** — KLUE-BERT(422MB)와 음성 인식
Whisper(150MB + 처리 시간). 메모리의 3분의 1이 한 번에 없어진다.

**다시 학습할 필요가 없다.** 지금 모델로 시험을 보되 담당 하나씩 눈을 가리면 된다. 모델은
학습할 때 이미 "한 담당이 없는 상황"을 25% 확률로 겪어서 이 조건을 안다.

```
전체 다 쓰면      46.19%
  글자 가리면      ?
  얼굴 가리면      ?
  목소리 가리면    ?
```

30분이면 끝난다. 이 결과로 엣지용 설계를 정한다.

## 9. 이 모델에 대해 자주 나올 질문들 — 기본부터 심화까지

AI 모델을 검토할 때 흔히 나오는 질문들(모델 카드·성능 심화·배포·윤리/공정성 항목)을 기준으로, 이 프로젝트에 대입해서 답할 수 있는 것과 아직 답하지 못하는 것을 정리했다.

### 9.1 기본적인 질문

**Q. 정확히 뭘 입력받고 뭘 출력하나?**
입력은 발화 하나에 대응하는 (오디오 wav 파일, STT 텍스트, 얼굴 크롭 프레임들) 세 가지. 출력은 7개 감정 클래스 각각에 대한 확률(소프트맥스)이고, 그중 가장 높은 확률의 클래스 하나를 최종 답으로 낸다(별도의 판단 기준값(threshold) 없이 단순히 "제일 확률 높은 것 선택" 방식 — argmax).

**Q. 어떤 소프트웨어/라이브러리로 만들었나?**
PyTorch(딥러닝 프레임워크), HuggingFace `transformers`(BERT 로딩), `emotiefflib`(MobileFaceNet 로딩), `librosa`(멜 스펙트로그램·운율 추출), `mediapipe`(얼굴 검출·정렬), OpenCV·PyAV·`soundfile`(영상/오디오 파일 처리), scikit-learn(평가지표 계산).

**Q. 학습은 어떤 장비로, 얼마나 걸리나?**
A100 80GB GPU 서버에서 학습. 배치 진행 로그로 역산하면 한 에폭(train 55,920개 전부 한 번씩 봄) 학습에 **약 6~7분** 정도 걸린다(437배치 기준, 정확한 총 학습시간을 별도로 기록해두진 않아서 로그 기반 추정치다). 실제 종료까지 걸린 에폭 수(6장 표, 21~70에폭)를 곱하면 버전 하나당 대략 3~8시간 정도로 추정된다.

**Q. 모델 용량(파일 크기)은 실제로 얼마나 되나?**
파라미터 1억 2,104만 개를 기준으로, 저장 정밀도에 따라: **fp32(기본) 약 461.7MB, fp16(절반 정밀도) 약 230.9MB, int8(양자화) 약 115.4MB.** 로봇처럼 저장공간·메모리가 제한된 장비에 올리려면 fp16이나 int8로 줄이는 압축(양자화) 작업이 필요하다 — 아직 시도 전(10장 계획 참고).

### 9.2 성능을 더 깊이 파고드는 질문

**Q. 어떤 감정을 제일 못 맞히나?**
**공포(fear)가 항상 가장 약한 클래스다.** v6+v7+v8 3중 앙상블 기준 precision 0.29 / recall 0.26 / f1 0.27로 7개 클래스 중 최하위(참고로 가장 잘 맞히는 건 happy, f1 0.65). 데이터 자체가 가장 적은 클래스(테스트셋 814개, 5.1절)라는 점과 맞물려 있다.

**Q. "전체적으로 잘한다"는 수치가 흔한 클래스(혐오)에 유리하게 쏠린 착시 아닌가?**
합리적인 의심이다. 그래서 두 종류의 F1을 구분해서 봐야 한다:
- **weighted F1**(지금까지 이 문서에서 주로 보고한 값, 예: 3중 앙상블 0.4814): 클래스별 데이터 개수만큼 비중을 줘서 평균 — 데이터 많은 혐오·행복을 잘 맞히면 점수가 높게 나옴
- **macro F1**(클래스 7개를 동등하게 취급): 3중 앙상블 기준 **0.45** — weighted(0.4814)보다 낮다. 이 차이(0.031)가 "데이터 적은 소수 클래스(공포 등)에서는 상대적으로 더 못한다"는 걸 보여주는 정직한 신호다.

**Q. 모델이 얼마나 확신을 가지고 예측하는지(calibration) 확인했나?**
**아직 안 했다.** 지금은 소프트맥스 확률 중 가장 높은 값을 그냥 최종 답으로 쓸 뿐, "모델이 90% 확신했을 때 실제로 90% 확률로 맞는지"(신뢰도 보정, calibration) 같은 검증은 하지 않았다. 로봇이 "판단이 애매하면 소극적으로 반응"하는 식의 행동을 하려면 이 검증이 필요하다.

**Q. 모델이 무엇을 근거로 판단했는지 설명할 수 있나?**
크로스 어텐션(4.5절)이 내부적으로 "어느 시점의 음성/텍스트/영상에 더 주목했는지" 가중치를 계산은 하지만, **이 가중치를 따로 뽑아서 시각화·분석하는 코드는 아직 없다.** "왜 이 판단을 내렸는지" 설명하는 기능은 현재 없음.

### 9.3 배포·실사용 관련 질문

**Q. 실제 로봇에 올리면 반응 속도(추론 지연시간)는?**
**아직 측정하지 않았다.** 지금까지는 정확도 개선에 집중했고, 실제 임베디드 장비에서 "발화 하나 넣고 답이 나올 때까지 몇 ms 걸리는지"는 별도로 재본 적이 없다. 세 개의 사전학습 백본(BERT 1.1억, MobileFaceNet, 자체 오디오 모델)을 다 돌려야 해서, 지금 크기 그대로는 실시간 로봇 반응에 부담이 될 가능성이 높다 — 앞서 나온 양자화·지식증류 계획(10장)이 필요한 이유다.

**Q. 목소리·얼굴 같은 민감한 생체 정보는 어떻게 다루나?**
지금 파이프라인은 원본에 가까운 오디오 wav 파일과 얼굴 크롭 이미지를 학습 서버 디스크에 그대로 저장해서 쓴다(`wav_path`, `face_frames_dir`). **개인정보·생체정보 보호 관점의 별도 처리(익명화, 접근 제한, 보관기간 정책 등)는 현재 이 프로젝트 범위에서 다루지 않고 있다** — 실제 서비스로 갈 때는 별도로 검토가 필요한 항목.

**Q. 데이터 라이선스는 문제없나?**
학습 데이터는 AI Hub(한국지능정보사회진흥원이 운영하는 공개 데이터 플랫폼)에서 받은 것이다. AI Hub는 통상 이용약관에 따라 연구·개발 목적 사용을 허용하지만, **정확한 이용 범위(상업적 이용 가능 여부, 재배포 제한 등)는 이 문서에서 확정적으로 답할 수 없다 — 실제 제품에 쓰기 전에 AI Hub 이용약관 원문을 다시 확인해야 한다.**

**Q. 성별·연령대 등에 따라 성능이 다르지 않나?(공정성)**
**확인하지 않았고, 지금 데이터·코드 구조상 확인하기도 어렵다.** 매니페스트에 화자의 성별·연령 같은 인구통계 정보 자체가 포함돼 있지 않아서, "특정 집단에서 유독 성능이 낮다"는 걸 지금은 점검할 수 없다.

### 9.4 아직 답하지 못하는 것 — 정직하게 정리

| 항목 | 현재 상태 |
|---|---|
| 신뢰도 보정(calibration) | 미검증 |
| 설명가능성(explainability) | 미구현 |
| 인구통계학적 공정성(성별·연령별 성능차) | 데이터에 관련 정보 자체가 없어 확인 불가 |
| 실제 로봇 하드웨어에서의 추론 속도 | 미측정 |
| 데이터 라이선스 최종 확인 | AI Hub 이용약관 원문 재확인 필요 |
| 개인정보(생체정보) 처리 정책 | 미정 |
| 화자(배우) 독립성 | ✅ **해결됨(8.5절)** — 현재 최고는 v11의 **46.19%**(8.8절). v12 두 시도는 모두 이를 넘지 못함(8.12절) |
| 데이터 최소 품질 기준 | 확인 완료 — 부실 샘플 0.3~1.8% 수준으로 문제없음(8장 3번) |

## 10. 앞으로 계획 — 로봇에 올릴 수 있는 크기로

**모델을 더 정확하게 만드는 것보다 "올라가게" 만드는 게 먼저다**(8.14절).

### 순서

**1. 무엇을 빼도 되는지 잰다** (재학습 없음, 30분)

담당 하나씩 눈을 가리고 시험을 봐서 기여도를 확인한다. 글자 담당을 빼도 되면 메모리의
3분의 1이 한 번에 사라진다.

**2. 엣지용으로 다시 설계한다**

목소리 담당(3.15억 개)은 어느 경우든 못 쓴다. 둘 중 하나로 간다:

| 안 | 크기 | 성능 |
|---|---|---|
| 예전 방식(멜)로 되돌리기 | 220만 개 (1400배 작음) | 목소리 단독 31.74% (지금 39.48%) |
| 큰 모델을 작은 모델이 흉내내게(증류) | 조절 가능 | 손실 적을 것으로 기대. 작업량 큼 |

**3. 로봇 코드를 다시 짠다**

살릴 것: 실시간 화면, 카메라, 자세·낙상 감지, 목소리 감지(VAD)

버릴 것: 표정 인식 모델(찍는 것보다 못함), 규칙 기반 합치기

다시 만들 것: 피로도 계산(눈금이 100배 어긋남), 신뢰도 표시(실제로 작동하게)

### 통합하면서 새로 확인할 것

- **걷기와 자원 나눠쓰기**: 같은 보드에서 보행 학습이 돌아간다. 감정 판단이 GPU를 오래
  잡으면 로봇이 비틀거린다. 순서를 정하는 설계가 필요하다.
- **실제 환경**: 학습 데이터는 드라마 촬영본(정면 얼굴, 깨끗한 소리)이다. 실제로는 각도도
  조명도 잡음도 다르다.
- **확신도**: 로봇이 "행복 51%"라고 했을 때 진짜로 51% 맞는지 확인한 적이 없다. 행동을
  정하는 시스템이라 중요하다.

### 보류

모델을 키우는 방향(더 큰 사전학습 모델, 층 늘리기)은 전부 보류한다. 젯슨에 안 들어간다.

다만 **크기와 무관한 것들은 여전히 유효**하다 — 감정 라벨 체계 재검토(혐오가 오분류를 다
빨아들이는 문제), 사용자별 맞춤(로봇은 같은 사람을 반복해 만나므로 잘 맞는다).

---|---|---|
| 정답의 74%는 소리로 정해진다 | 맞음 | 아니오 |
| 모델이 감정보다 촬영 맥락을 3배 담는다 | 맞음 | 아니오 |
| 사람마다 감정 표현 방향이 다르다 | 맞음 | 아니오 |
| 24층에 감정 정보가 더 많다 | 맞음 | 아니오 |
| 모의고사 기준 선택이 옳다 | 맞음 | **규칙 확정** |

**무엇이 문제인지 아는 것과 그걸 고치는 것은 다른 일이다.**

반면 **로봇 코드에는 확실히 고칠 게 있다**(8.11절): 신뢰도 표시가 실제로는 안 쓰이고, 피로도가 10초 만에 최대가 되고, 설명서에 없는 기능이 적혀 있고, 표정 모델은 찍는 것보다 못하다.

**목표(60%)를 포기하는 게 아니라 순서를 바꾸는 것이다.** 로봇을 완성해두면 나중에 모델만 갈아끼우면 된다.

### 할 일

**살릴 것**: 실시간 화면, 카메라, 자세·낙상 감지, 음성 인식(STT)

**바꿀 것**: 표정 인식 모델 → 우리 트리모달 모델(46.19%), 규칙 기반 융합 → 학습된 융합

**다시 만들 것**: 피로도 계산(눈금이 100배 어긋남), 신뢰도 표시(실제로 작동하게)

**가장 큰 변화**: 지금 로봇은 **목소리 톤을 아예 안 쓴다.** 말을 글자로 바꾸고 톤은 버린다. 그런데 정답의 74%가 소리로 정해지므로, 가장 중요한 신호를 통째로 버리고 있었다.

### 나중에

모델 쪽 후보들(소리 담당 키우기, 다른 사전학습 모델, 감정 라벨 체계 재검토, 사용자별 맞춤)은 보류한다. 로봇을 만들면서 실제 환경 정보가 쌓이면 그때 근거를 갖고 다시 고른다.
